# data/book 目录管理规范

这个目录只用 Markdown 管理书籍内容和书籍元数据，不使用 JSON 作为书籍索引。

## 目录结构

每一本书一个独立目录：

```text
data/book/
  提示.md
  书籍名称/
    README.md
    node.md
    days/
      day-1.md
      day-2.md
```

也可以不用 `days/`，直接在书籍目录下放 `01-xxx.md`、`02-xxx.md` 作为章节文件。

## 书籍 README.md 必填信息

每本书的 `README.md` 是书籍元数据入口，PHP 会扫描它生成 `/books` 列表。

```yaml
---
type: book
id: unique-book-id
title: "书籍标题"
cover: "📘"
description: "一句话说明这本书解决什么问题"
created_at: "2026-05-18"
sort_order: 10
progress: 0
tags:
  - 标签1
  - 标签2
purpose: "这本书的目的"
summary: "这本书的总结"
prediction: "学完后的预测变化"
---
```

## 内容要求

每本书的 `README.md` 正文至少包含：

1. 计划：这本书怎么学、分几章、每天或每章做什么。
2. 目的：这本书要解决的核心问题。
3. 总结：这本书的核心结论。
4. 预测：读完并执行后，预期会带来什么变化。
5. 目录：指向具体章节文件。

## 每章题库文件

每个章节文件旁边都要有一个对应的题库文件。题库文件命名规则：

1. `days/day-1.md` 对应 `days/day-1.quiz.md`
2. `01-核心概念.md` 对应 `01-核心概念.quiz.md`

题库文件包含测试题、参考答案、总结、预测。格式固定如下，PHP 会自动解析，并把测试题提供给 `/books` 页面：

```md
## 测试题

1. 这里写题目
- A. 选项一
- B. 选项二
- C. 选项三
- D. 选项四
答案：C
解析：这里写为什么选 C

2. 这里写第二题
- A. 选项一
- B. 选项二
- C. 选项三
- D. 选项四
答案：A
解析：这里写为什么选 A

## 参考答案

1. C。这里写完整参考答案。
2. A。这里写完整参考答案。

## 本章总结

这里写本章核心结论。

## 本章预测

这里写学完并执行后，预期会带来的变化。
```

## 约定

1. 新增书籍时，只需要新增一个目录和 `README.md`，不需要改 PHP 代码。
2. `README.md` 的 `type` 必须是 `book`，否则不会进入书籍列表。
3. 标签用 YAML 列表，不用 JSON 数组。
4. 章节优先使用 `days/day-N.md`；如果不是课程型内容，可以使用 `01-标题.md` 这种根目录章节。
5. 测试题、参考答案、总结、预测必须写在对应 `.quiz.md` 中，不写在前端代码或 JSON 文件里。
